# Architecture

`src/smoke.c` is portable C11. It calls the injected `cgjre_platform` interface from `include/cgjre/platform.h`. The host and gint entry points provide the interface. This is only a display/key/exit smoke boundary; VM and MIDP interfaces will be designed against actual fixture needs in later milestones.

Planned ownership: `src/archive` reads JARs; `src/vm` parses and executes classes; `src/classlib` implements built-ins; `src/midp` owns lifecycle and rendering; `src/platform/gint` and `src/platform/host` provide hardware services. Empty directories mark planned components, not implemented ones.

M1 now has `src/archive/zip.c` and `manifest.c`. The ZIP reader receives a random-access read callback plus the known file size. It scans the bounded EOCD tail, indexes bounded central-directory metadata, checks local headers and payload extents, and allocates only index metadata or one requested entry. The host file adapter is outside the portable archive code. Raw DEFLATE is streamed through a 4 KiB input buffer into an exact-size bounded output allocation using pinned miniz tinfl; CRC and length are checked. Data-descriptor archives use central-directory sizes. The class parser in `src/vm/classfile.c` owns its metadata arrays but borrows the input byte buffer, which its caller must retain. It accepts class versions 45.3 and 46.0 and validates the supported constant pool, modified UTF-8, member descriptors, Code bounds, exception ranges, and bounded attributes. CLDC `StackMap` is skipped by length; this is not CLDC verification.

Main manifest attributes are case-insensitive and MIDlet declarations are parsed from `MIDlet-n` values. The class parser retains ConstantValue indices, SourceFile, and line number metadata. The bytecode scanner in `src/vm/bytecode_scan.c` counts instruction starts and checks variable-length switch and wide operand structure; it does not verify branch targets or execute instructions. The host inspector lists static constant-pool references and flags known out-of-scope API families. References may be unreachable, and no API linkage or runtime behavior is proven.

M2 uses `src/vm/interpreter.c`. A Java slot stores 32 bits and an explicit kind. `int` values use their modulo-2³² bit pattern. References use 32-bit handles with zero reserved for null; C pointers never occupy Java slots. A future category-2 `long` uses adjacent high and low slots, both tagged, but long operations are not implemented yet. Each Java call has a bounded explicit frame containing a method, bytecode offset, locals, operand stack, and validated instruction boundaries. The fixture runner starts at a static `(I...)I` method; its class hierarchy must end at `java/lang/Object` and contain no class initializer. `invokestatic` resolves integer methods from the same external JAR. Unsupported instructions and features return explicit errors. The host `--eval-class` and `--eval-jar` commands invoke this same portable core; they are semantic fixture runners, not MIDlet launch or a thread scheduler. The step limit ends a fixture run and does not switch Java threads.

`src/archive/suite.c` owns extracted class bytes and parsed metadata until suite close. It loads class entries on demand through the shared bounded ZIP reader, caches up to 128 classes, checks the internal class name against the requested path, and rejects application definitions in `java/` and `javax/`. The VM receives class resolution as a callback; the host supplies a file-backed ZIP source, while a future gint storage backend can supply the same interface. Hierarchies are loaded on demand, checked for cycles, and capped at 16 classes. Classes requiring initialization or Java exceptions still fail explicitly.

The VM now holds primitive arrays behind numbered 32-bit handles, with zero reserved for null. Reference slots in locals and operand stacks carry the reference kind explicitly. `newarray` supports boolean, byte, char, short, and int arrays; matching load/store instructions check array type, index, and null handle. Boolean and byte elements use eight-bit storage; `baload` sign-extends and `bastore` truncates to eight bits, matching the [JVM instruction text](https://docs.oracle.com/javase/specs/jvms/se8/html/jvms-6.html). Handles and payloads are retained until the fixture run ends, then released together. This is not garbage collection, and Java exceptions are still reported as explicit VM statuses.

The same handle table holds class instances with a base-to-derived field layout. Instance fields have default values and one slot each for `int` or reference descriptors; long, float, and double fields are rejected. `new` creates an uninitialized handle. `invokespecial` runs matching `(I...)V` constructors through the superclass chain and recognizes `java/lang/Object.<init>()V` as a narrow built-in. Each constructor must complete its direct superclass call before field access or `return`; aliases in the allocating caller become initialized only after the outermost constructor returns. `getfield`/`putfield` resolve by owner, name, and descriptor, including inherited and hidden fields. `invokevirtual` validates the symbolic method in the named owner and dispatches by name and descriptor from the receiver's most-derived class, for integer-return methods with integer arguments. Null, uninitialized, wrong-type, missing, and prohibited final-field access fail explicitly. Interface dispatch, other signatures, Java exception objects, and GC remain unsupported. These checks are runtime guards, not a full bytecode verifier.

`anewarray`, `aaload`, and `aastore` support reference arrays of `java/lang/Object` or a supported non-interface class. Element stores accept null or an instance whose loaded class chain includes the declared component class. `instanceof` and `checkcast` use the same class chain for ordinary classes and supported primitive or reference array descriptors; failed casts return a VM status until Java exceptions exist. Interface targets, multidimensional arrays, and complete array covariance for fields are not implemented.

`docs/opcodes.csv` has one row per byte using [Oracle's opcode table](https://docs.oracle.com/javase/specs/jvms/se8/html/jvms-7.html). `m2_integer_slice`, `m2_reference_slice`, `m2_array_slice`, and `m2_category1_slice` denote executable operations only within the restrictions above. Partial statuses limit constants, calls, object creation, fields, constructors, and arrays to the described subset. All other statuses are explicit.
