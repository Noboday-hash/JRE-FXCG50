# Architecture

`src/smoke.c` is portable C11. It calls the injected `cgjre_platform` interface from `include/cgjre/platform.h`. The host and gint entry points provide the interface. This is only a display/key/exit smoke boundary; VM and MIDP interfaces will be designed against actual fixture needs in later milestones.

Planned ownership: `src/archive` reads JARs; `src/vm` parses and executes classes; `src/classlib` implements built-ins; `src/midp` owns lifecycle and rendering; `src/platform/gint` and `src/platform/host` provide hardware services. Empty directories mark planned components, not implemented ones.

M1 now has `src/archive/zip.c` and `manifest.c`. The ZIP reader receives a random-access read callback plus the known file size. It scans the bounded EOCD tail, indexes bounded central-directory metadata, checks local headers and payload extents, and allocates only index metadata or one requested entry. The host file adapter is outside the portable archive code. Raw DEFLATE is streamed through a 4 KiB input buffer into an exact-size bounded output allocation using pinned miniz tinfl; CRC and length are checked. Data-descriptor archives use central-directory sizes. The class parser in `src/vm/classfile.c` owns its metadata arrays but borrows the input byte buffer, which its caller must retain. It accepts class versions 45.3 and 46.0 and validates the supported constant pool, modified UTF-8, member descriptors, Code bounds, exception ranges, and bounded attributes. CLDC `StackMap` is skipped by length; this is not CLDC verification.

Main manifest attributes are case-insensitive and MIDlet declarations are parsed from `MIDlet-n` values. The class parser retains ConstantValue indices, SourceFile, and line number metadata. The bytecode scanner in `src/vm/bytecode_scan.c` counts instruction starts and checks variable-length switch and wide operand structure; it does not verify branch targets or execute instructions. The host inspector lists static constant-pool references and flags known out-of-scope API families. References may be unreachable, and no API linkage or runtime behavior is proven.

M2 begins with `src/vm/interpreter.c`. A Java slot stores 32 bits and an explicit kind. `int` values use their modulo-2³² bit pattern. References use 32-bit handles with zero reserved for null; C pointers never occupy Java slots. A future category-2 `long` uses adjacent high and low slots, both tagged, but long operations are not implemented yet. Each Java call has a bounded explicit frame containing a method, bytecode offset, locals, operand stack, and validated instruction boundaries. This slice starts at a static `(I...)I` method in a class directly extending `java/lang/Object`, with no class initializer, synchronized method, or exception table. `invokestatic` resolves static integer methods from the same external JAR. Unsupported instructions and features return explicit errors. The host `--eval-class` and `--eval-jar` commands invoke this same portable core; they are semantic fixture runners, not MIDlet launch or a thread scheduler. The step limit ends a fixture run and does not switch Java threads.

`src/archive/suite.c` owns extracted class bytes and parsed metadata until suite close. It loads class entries on demand through the shared bounded ZIP reader, caches up to 128 classes, checks the internal class name against the requested path, and rejects application definitions in `java/` and `javax/`. The VM receives class resolution as a callback; the host supplies a file-backed ZIP source, while a future gint storage backend can supply the same interface. Root and callee classes in this integer slice must directly extend `java/lang/Object`; classes requiring initialization or Java exceptions still fail explicitly.

The VM now holds primitive arrays behind numbered 32-bit handles, with zero reserved for null. Reference slots in locals and operand stacks carry the reference kind explicitly. `newarray` supports boolean, byte, char, short, and int arrays; matching load/store instructions check array type, index, and null handle. Boolean and byte elements use eight-bit storage; `baload` sign-extends and `bastore` truncates to eight bits, matching the [JVM instruction text](https://docs.oracle.com/javase/specs/jvms/se8/html/jvms-6.html). Handles and payloads are retained until the fixture run ends, then released together. This is not garbage collection, and Java exceptions are still reported as explicit VM statuses.

The same handle table now holds instances of classes that directly extend `java/lang/Object`. Instance fields have default values and one slot each for `int` or reference descriptors; long, float, and double fields are rejected. `new` creates an uninitialized handle. `invokespecial` runs a matching `(I...)V` constructor in a frame and recognizes `java/lang/Object.<init>()V` as a narrow built-in. The constructor must complete that superclass call before field access or `return`; aliases are promoted to initialized references only when the constructor returns. `getfield`/`putfield` resolve by class, name, and descriptor and reject null, uninitialized, wrong-type, missing, or prohibited final-field access. Inherited fields and methods, virtual calls, Java exception objects, and GC remain unsupported. These checks are runtime guards, not a full bytecode verifier.

`docs/opcodes.csv` has one row per byte using [Oracle's opcode table](https://docs.oracle.com/javase/specs/jvms/se8/html/jvms-7.html). `m2_integer_slice`, `m2_reference_slice`, `m2_array_slice`, and `m2_category1_slice` denote executable operations only within the restrictions above. Partial statuses limit constants, calls, object creation, fields, constructors, and arrays to the described subset. All other statuses are explicit.
