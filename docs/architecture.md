# Architecture

`src/smoke.c` is portable C11. It calls the injected `cgjre_platform` interface from `include/cgjre/platform.h`. The host and gint entry points provide the interface. This is only a display/key/exit smoke boundary; VM and MIDP interfaces will be designed against actual fixture needs in later milestones.

Planned ownership: `src/archive` reads JARs; `src/vm` parses and executes classes; `src/classlib` implements built-ins; `src/midp` owns lifecycle and rendering; `src/platform/gint` and `src/platform/host` provide hardware services. Empty directories mark planned components, not implemented ones.

M1 now has `src/archive/zip.c` and `manifest.c`. The ZIP reader receives a random-access read callback plus the known file size. It scans the bounded EOCD tail, indexes bounded central-directory metadata, checks local headers and payload extents, and allocates only index metadata or one requested entry. The host file adapter is outside the portable archive code. Raw DEFLATE is streamed through a 4 KiB input buffer into an exact-size bounded output allocation using pinned miniz tinfl; CRC and length are checked. Data-descriptor archives use central-directory sizes. The class parser in `src/vm/classfile.c` owns its metadata arrays but borrows the input byte buffer, which its caller must retain. It accepts only class version 45.3 and validates the supported constant pool, modified UTF-8, member descriptors, Code bounds, exception ranges, and bounded attributes. CLDC `StackMap` is skipped by length; this is not CLDC verification.

Main manifest attributes are case-insensitive and MIDlet declarations are parsed from `MIDlet-n` values. The class parser retains ConstantValue indices, SourceFile, and line number metadata. The bytecode scanner in `src/vm/bytecode_scan.c` counts instruction starts and checks variable-length switch and wide operand structure; it does not verify branch targets or execute instructions. The host inspector lists static constant-pool references and flags known out-of-scope API families. References may be unreachable, and no API linkage or runtime behavior is proven.

M2 begins with `src/vm/interpreter.c`. A Java slot stores 32 bits and an explicit kind. `int` values use their modulo-2³² bit pattern. Future references use 32-bit handles with zero reserved for null; C pointers never occupy Java slots. A future category-2 `long` uses adjacent high and low slots, both tagged, but long operations are not implemented yet. Each Java call will have a bounded explicit frame containing a method, bytecode offset, locals, operand stack, and validated instruction boundaries. This slice has one active frame and executes only static `(I...)I` methods in classes extending `java/lang/Object`, with no class initializer, synchronized method, or exception table. Unsupported instructions and those features return explicit errors. The host `--eval-class` command invokes this same portable core; it is a semantic fixture runner, not MIDlet launch or a thread scheduler. The step limit ends a fixture run and does not switch Java threads.

`docs/opcodes.csv` has one row per byte using [Oracle's opcode table](https://docs.oracle.com/javase/specs/jvms/se8/html/jvms-7.html). `m2_integer_slice` means executable only within the restrictions above; `partial_integer_only` further limits `ldc`/`ldc_w` to integer constants and `wide` to integer load/store/increment forms. All other statuses are explicit.
